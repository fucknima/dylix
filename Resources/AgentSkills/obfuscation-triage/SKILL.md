## 先分类，后选择方法

读取所选二进制的 overview 和实际可用的 binary_obfuscation_scan，记录加密范围、节布局、符号、字符串、分支与疑似间接派发。高熵可能来自压缩或资源，少字符串可能是 strip 或语言特征；任何单一指标都不足以认定加壳、OLLVM 或自定义 VM。

FairPlay 加密标记、资源 AES、字符串 XOR、Base64 文本与控制流平坦化不是同一问题。先找消费数据的函数、输入长度和真实调用点，再决定是字节变换、静态数据流还是需补充运行证据。现有工具不包含万能未知密钥解密器；不要声称当前已支持任意动态脱壳或 Frida 后端。

## 已知编码的有界验证

binary_inspect(action=decode) 接受切片内 file_offset 和 byte_count。Base64 要选择实际 ASCII 编码内容并排除末尾 NUL；Hex 是解码文件内 ASCII 十六进制文本，不是把任意机器字节再转 hex；XOR 必须提供有依据的已知 key_hex。不要把 VM 地址直接传成文件偏移，不要凭空猜 key 后宣称恢复成功。

一次失败后先核对偏移、长度、切片、字符集合和终止符，修正有证据的输入；不重复相同请求。解码成功后核对输出长度、格式、可解析字段与使用点，只是出现可打印文本不能证明算法正确。工具只返回受限摘录时保留截断信息。

## 控制流与算法恢复

用 functions → disassemble / cfg / xrefs 缩小到目标函数，按需借助 sandbox_reverse 的 decompile / pcode。平坦化时记录 dispatcher、状态变量、状态更新与跳转关系，间接目标未解析就明确缺口。对可确定的常量、位运算、边界、字节序和调用顺序给出等价伪代码，并用已知输入输出校验。

若需要额外运行证据，列明具体缺少的状态/数据以及当前可用的 FLEX、日志或用户提供样本途径，不伪造动态追踪结果。不能因某条分支当前未走就删除它，也不能把反编译器自动生成的 switch 当原始源码结构。

输出采用“观察特征 → 可检验假设 → 工具/参数依据 → 已验证结果 → 剩余限制”，避免用“已完全解密/已完全还原”覆盖未验证部分。
