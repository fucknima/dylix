# Build268：回读入口复用与指南保留

## 实际会话证据

检查用户提供的单会话 ZIP：共 114 次 read_context；同 ref/offset 重复请求额外出现 56 次，单页最多 8 次；46 次回读目标是开发指南。没有发现将 read_context 的结果再作为 result: 目标回读的调用，所以不把这个案例描述成已确认的递归套娃。

## 改动

- read_context 增加当前实际出站上下文参数。只有相同 canonical ref、SHA、范围及内容确实仍在当前可见工具结果或工作证据中，才返回 already_visible 复用回执，避免重复传回整页。回执保留页范围及 next_offset，不伪称整个原文已读取。
- 已经离开当前上下文的历史页依旧可取；不按“曾经读过”无条件禁止读取。原始归档读取接口仍精确返回原文。
- 同批工具中先前已得到的结果也作为下一轮可见内容，避免一批中重复回读。
- 工作证据保留最多四个已经加载的指南（保留版本和原内容，仍计入 24 KiB 证据预算）；完整指南原文相同则直接复用。
- 继续保留 Build267 的源码工作证据、修改文件局部失效、行范围重叠识别和最终循环止损。

## 验证

- 132 项上下文测试通过，覆盖可见重复页/重叠范围复用、被移出上下文的页精确取回、新分页、工作证据页及完整已加载指南复用。
- 原始 114 次回读请求离线重放中，33 次可用实际出站上下文直接复用，省去重复返回的原文片段共 42192 UTF-8 字节。这是固定原始请求序列的离线结果，不是实际模型节省的 token 或账单。
- 连续运行、恢复、真实重复片段回放、正常长任务及导航生命周期回归通过。
- 原始用户会话不放入发布文件。没有用用户的真实模型接口重新发起任务，不声称零循环。
