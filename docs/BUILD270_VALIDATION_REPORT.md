# Dylix Build270 回读与循环检验报告

检验日期：2026-11-12。版本：1.1.2（270），上下文策略：270。
对照基线：本轮开始时保存的 Build269 源码快照；使用独立目录编译，没有拿修改后的源码冒充旧版。

## 结论

导致频繁回读的一条确定性原因已修复：预算充足时，近期合理大小的工具结果不再因固定 16 KiB 门槛立刻被替换成引用。历史读取可直接取文本字段和行范围；当前可见的原文返回复用位置。重复观察增加一次局部证据纠偏，不只是更快暂停。

离线与模拟验证通过；不能据此宣布真实用户循环问题已经彻底解决。本报告没有真实在线模型试验、真实 token/费用/缓存测量或真机运行结果，不给循环概率。

## 实现内容与剩余范围

原方案共 28 项：25 项实现完成，3 项部分完成，逐项状态见 AGENT_CONTEXT_IMPROVEMENT_PLAN.md。

1. 近期完整工具批次在预览前进入保护区；总上限和超大参数/结果边界继续存在。
2. 工作源码按路径、版本、行区间保留；相邻/重叠内容一致才合并。真实成功修改只淘汰对应旧文件；历史旧副本不覆盖新版本。指南按 topic 保留最新记录，小配置、模型计划和待应用提案独立保留。
3. read_context 新增 content/text/message/error 字段及行范围、长行列偏移。返回原始工具、版本、位置和下一页；旧 offset 接口继续兼容。Unicode 组合字符和非法/极大参数有边界检查。
4. 以实际发送的上下文确认可见性，覆盖原始工具结果、工作源码、历史页；已经离开当前上下文时仍能合法取回原文。
5. 重复观察时补有限历史证据、近期失败和阻碍，结合当前工作区与最新用户目标纠偏一次；不自动批准、不重放副作用、不替换模型。最终无进展保护保留。
6. 动作目标、结果版本与范围联合比较；不同查询的相同空结果不立即视为同一个动作；正常分页、变化错误、修改后验证继续允许。
7. 流式正文连续重复有界停止，不自动重发；代码/表格等采用保守排除，明确重复请求放行。保守规则存在漏检可能，不称通用语义循环识别。
8. 增加本机工具次数、历史目标工具、重复观察、纠偏、终态及纠偏后实际修改记录；会话导出记录构建与策略。变化进度/工作证据移向消息尾部，内部标记不作为正常正文展示。

部分完成的三项：基于可靠模型 token 窗口自动预留输出尚未实现；跨会话纠偏完成率聚合界面尚未新增；真实提供商缓存/总费用测量尚未执行。当前用户字节保护上限仍有效，不能与模型 token 窗口混算。

## 数据一：近期原文保留与复用，600 组配对

两个版本各执行相同 600 个合成源码样本，覆盖 64、128、256、512、1024 KiB 五档预算，每档 120 个样本。

- 旧版：近期源码完整保留 0/600；可见原始结果复用 0/600。
- 新版：近期源码完整保留 600/600；可见原始结果复用 600/600。
- 两版保护拦截均为 0/600。
- 整理后请求 JSON 累计字节：旧版 5,050,200；新版 16,057,200。

新版保留了旧版移走的真实源码，单轮输入明显增加，约为旧版 3.18 倍。两版工具 schema 也有变化，不能把该数字归因于单一变量，更不能把“少卸载/多保留”说成费用下降。本组没有接模型决策，无法测量后续少回读抵消了多少输入。

另有 600 组确定性投影测试：5,498 条断言通过；覆盖字段范围、完整原文复用、内容不可见后恢复、无效参数、75,000 UTF-16 量级含中文/emoji 的超长行重建。

## 数据二：真实运行时 + 模拟模型闭环，180 对轨迹

不是在线模型。脚本运输层把请求送入预设响应器，但使用实际 AIRuntime、上下文投影及工具处理代码。三种协议名称各 30 个种子 × 两种响应器，共每版 180 次；协议名称不能当作三家真实模型验证。独立提供商 wire fixture 另测协议转换。

可响应纠偏的响应器在看到恢复提示后，必须真正调用 read_file 获取缺失文件，再完成分析。它是专门构造的可恢复场景，不代表模型通常会遵从提示；任务验收不包含真实补丁或构建。

- 可恢复组：旧版 0/90 完成、90/90 暂停；新版 90/90 完成并执行缺失源码读取、0/90 暂停。
- 这组历史读取：旧版 1,320 次 → 新版 90 次，减少 **93.18%**。
- 始终故意重复组：两版均 90/90 有限暂停。新版历史读取 1,200 次，旧版 1,320 次。暂停只算兜底通过，不算任务解决。
- 全部轨迹：历史读取 2,640 → 1,290 次；总请求 2,640 → 1,470 次。新增 90 次有效源码读取已纳入请求统计。
- 两版均 180/180 保持工具调用/结果配对，未越过测试驱动 35 请求上限。
- 新版另实测运行时流式正文：普通任务的重复输出被暂停；明确要求重复输出正常完成；两种都只发送一次请求，不自动重试。

本组 93.18% 达到方案对“固定可恢复重复场景”的 80% 目标，但不可外推为真实生产回读降幅或循环概率。

- 历史中有 114 次 read_context。按原调用序列回放，旧版 47 次复用，避免回传 61,852 UTF-8 字节；新版 48 次复用，避免回传 63,056 字节。
- 最终请求文本 JSON：旧版 140,980 字节；新版 177,427 字节。新版保留工作证据约 74,498 字节。
- 这是相同历史记录的固定序列，没有让真实模型重新选下一步；114 次调用并没有凭空减少到 66 次。
- 新版有限循环保护在三个历史重复窗口均能提前于原记录的用户干预暂停；它不能证明暂停后模型会自行完成原任务。

这个结果只显示该真实记录的额外复用改善有限，不能拿合成场景 93.18% 覆盖它。
