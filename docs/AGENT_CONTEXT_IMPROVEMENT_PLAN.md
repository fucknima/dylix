# Dylix Agent 回读与循环改善方案

日期：2026-11-12。基线：发布版 1.1.2 Build269。
状态：已推进至 Build271，完成新增压力预算、源码定位、回答风格及真实 API 对照，并以 iOS26 SDK 构建。以下原 Build270 记录保留历史语境；最新结果见 BUILD271_VALIDATION_REPORT.md。勾选仅表示对应实现落地，未验证的费用、模型窗口及真机范围仍未完成。

## 1. 目标与结论

目标是让 AI 持续完成当前任务，减少不必要历史回读、无进展重复调用和重复叙述，同时保留正常研究、长任务、必要复查及修改后的验证能力。

核心顺序：先减少信息被过早移走，再改善读取粒度与任务交接，最后加入可恢复的循环纠偏。仅调高预算、缩短暂停阈值、禁止 read_context 都不能代替这些改动。

不能承诺循环概率为零。此次没有在线多模型重复试验，不能报告发生概率。其他 Agent 的界面未显示“回读”也不能证明它们没有内部历史整理或文件再读取。

## 2. 已确认事实与待验证推断

### 2.1 用户会话证据

来自本地导出会话，865 条消息、618 条过程记录。导出没有记录 App 构建号，无法确认一定为 Build265。

- read_file 264 次、read_context 114 次、search_text 73 次。
- 114 次 read_context 中，46 次针对开发指南、16 次针对 read_file、11 次针对配置、11 次针对头文件，其余针对其他原文。
- 相同 ref + offset 额外重复 56 次，某一页最多读取 8 次。
- 没有发现 read_context 结果再指向另一条 read_context 结果的递归调用。不能把这次事件归因为已经证实的“无限递归引用”。
- Build269 固定调用离线回放中，47 次回读可复用实际可见内容，少回传 61,852 UTF-8 字节；这不是少调用 47 次，更不是循环概率或实际计费节省。

### 2.2 Dylix 源码确认的薄弱处

1. `TFAIContextProjection.m` 会先处理所有完整工具批次：参数字符串超过 1,024 UTF-8 字节便生成占位引用；非 read_context 结果超过 16 KiB 便生成预览。随后才执行“保护最近两个批次”的旧历史折叠逻辑。因此最近批次受保护，并不等于最近原文完整保留。即使总预算充足，也可能刚读就被移走。
2. 默认原文接口每页最多 4,096 UTF-16 单位，分页对象是整个序列化 JSON。模型为了某个源码字段，可能得跨过包装字段、转义和多个页面。
3. Build269 工作证据最多 8 项、单源码片段 5,000 UTF-16 单位、扫描最近 512 条消息；指南最多 4 项且单指南最多 6 KiB。它缓解遗忘，但无法保证当前复杂修改所需内容完整常驻。
4. 已有重复检测和进度索引，但当前主要是向下一轮追加提醒；重复严重时暂停。缺少“诊断缺口→补齐必要原文→只纠偏一次→检查是否产生新进展”的明确恢复流程。
5. `VisiblePage` 当前能匹配历史页包装和 loaded_guides，但没有直接按当前原始 tool_call_id 对齐 `result:<id>`；完整原始工具结果仍可见时，也可能重复回传同一原文。
6. 当前进度计划是模型自报，不是已验证执行结果；只靠增加 update_plan 不能解决工具结果反复缺失。
7. 工作证据在系统提示之后、常规历史之前插入，稳定性和提供商缓存命中需要测量；不能默认每轮重写前缀一定更省钱。

本轮最小复现（实际编译 Build269 的投影代码，256 KiB 预算）：

- 源码结果 21,445 UTF-8 字节，完整请求 23,427 字节，依然触发最近结果卸载。证明“总预算充足也会过早卸载”，不是假设。
- 将完整原始工具结果作为当前可见消息传入回读接口，仍返回 4,096 UTF-16 单位，`already_visible` 为否。证明存在一种漏判复用的情形。
- 使用临时诊断程序验证，未修改运行时代码。诊断只验证机制，不代表真实模型必然循环。

这些条件如何共同改变真实模型行为，仍需对照试验。不能仅凭源码推断一个百分比。

## 3. 上游实现与适用取舍

本轮读取实际源码，不以产品截图代替实现依据。OpenCode 当前主干结构已变化，旧 session/processor 路径不存在，改为实际仓库中的 core 路径。GitHub API 公共限流后采用匿名浅克隆读取源码，未使用用户 PAT。

### Aider：把当前文件与历史分开

- 源码：<https://github.com/Aider-AI/aider/blob/main/aider/coders/base_coder.py>，`get_files_content`、`format_chat_chunks`；<https://github.com/Aider-AI/aider/blob/main/aider/history.py>。
- 做法：当前文件、只读文件、历史摘要、当前消息分开组装；压缩较早历史并保留尾部。
- 应用：建立按当前任务选择的工作文件区，确保即将编辑的片段仍可见。采用有界范围，不照搬每次发送全文件，避免大头文件撑满窗口。

### OpenCode：按资源读取，输出可检索，摘要可继续工作

调研提交：`4f51455a5da7859e4f1a1b6abcc54b67bf7b7a4b`。

- 压缩：<https://github.com/anomalyco/opencode/blob/4f51455a5da7859e4f1a1b6abcc54b67bf7b7a4b/packages/core/src/session/compaction.ts>。结合模型容量和近期尾部预算，交接包含目标、约束、决定、工作状态和下一步；后台摘要尽量利用原提示缓存。
- 读取：<https://github.com/anomalyco/opencode/blob/4f51455a5da7859e4f1a1b6abcc54b67bf7b7a4b/packages/core/src/tool/plugin/read.ts>。按资源路径和行范围读取，提示优先一次足量读取，定位使用搜索。
- 输出：<https://github.com/anomalyco/opencode/blob/4f51455a5da7859e4f1a1b6abcc54b67bf7b7a4b/packages/core/src/tool-output.ts>。截断时保存完整输出，显式返回保存位置或保存失败。
- 应用：从“遍历历史 JSON”转向“按字段/行范围取当前需要的信息”，清晰标记未返回范围、完整存储状态。摘要模型调用有成本，不默认每几轮额外调用一次模型。

### OpenHands：动作与结果成对比较，一次明确纠偏

调研提交：`9f7d5cb11b1256c1878f5584a657401feca9ad16`。

- 检测：<https://github.com/OpenHands/software-agent-sdk/blob/9f7d5cb11b1256c1878f5584a657401feca9ad16/openhands-sdk/openhands/sdk/conversation/stuck_detector.py>。比较动作/观察、动作/错误、交替模式及无进展独白；同一错误序列只发一次针对性 nudge，避免提示本身循环。
- 交接：<https://github.com/OpenHands/software-agent-sdk/blob/9f7d5cb11b1256c1878f5584a657401feca9ad16/openhands-sdk/openhands/sdk/context/condenser/prompts/summarizing_system.j2>。保留用户目标、任务状态、已完成/待完成、代码状态、错误及测试。
- 应用：记录真实执行证据与下一缺口，局部纠偏而非自动重试整任务；用户新要求立即覆盖旧动作。模型自报任务进度与真实成功回执分开。

### Gemini CLI：多种循环信号，保护正常调试

- 源码：<https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/services/loopDetectionService.ts>（本轮读取 main，未固定提交，不将其参数视为永久默认值）。
- 做法：检查长度 1–5 的重复工具调用周期；流式重复文本另行识别，避开代码块等合法重复结构；语义诊断明确区分不同文件、不同修改、变化的错误与真实无进展。还有额外 LLM 检测机制。
- 应用：调用参数与结果联合判断、区分正常分页和版本变化、检测纯文本重复。暂不默认接入额外付费“检测模型”，先用确定性本机规则和有界恢复。

### OpenMinis / DeepAgents：保留尾部与任务交接

- OpenMinis：<https://github.com/OpenMinis/OpenMinis/blob/main/src/ios/Agent/Chat/AIChatViewModel%2BCompaction.swift>。
- DeepAgents：<https://github.com/langchain-ai/deepagents/blob/master/libs/deepagents/deepagents/middleware/summarization.py>。
- 应用：摘要保留已做/未做和关键路径，近期工具批次完整配对；缺失内容可精确取回。不能用摘要猜测代码、审批、测试成功。

## 5. 对照验证与发布门槛

### 固定基线

保存 Build269 与新实现独立测试基线。使用相同任务、模型、提供商、权限、温度/推理设置、初始工作区及相同原始历史。离线调用序列只用于协议/数据验证，不能代替在线模型决策试验。

### 测试任务

至少包含：开发指南后修改插件、单个 20–80 KiB 源码、超大头文件定位、导出与产物交付、补丁失败后修正、长构建轮询、从旧会话继续、用户中途修正与后台恢复。

确定性测试另覆盖：重复同页、变化分页参数但重叠源码、交替工具重复、旧历史覆盖新版本、外部文件变化、JSON 大字段、原文不可见后的合法重读、多提供商原生回放与工具配对。

### 记录指标

- 任务完成与正确性，实际变更是否通过验证。
- 非必要历史回读次数；同 ref/版本/范围在无变化情况下的重复次数。
- 真实输入/输出/缓存 token、总费用、请求轮数及耗时。所有 API 请求都纳入，不忽略摘要或纠偏的额外花费。
- 循环事件：至少 3 个观察轮次出现同一动作或短周期动作，且无新增信息、状态变化或必要验证；人工复核排除合法分页/调试。此为评测定义，不直接等同生产触发阈值。
- 误拦、漏拦、一次纠偏后恢复成功及无法恢复的次数。

### 建议门槛（目标，尚未测得）

- 确定性测试全部通过，原文可恢复、权限、签名续接和用户修正不回归。
- 固定可解重复读取场景均能经一次纠偏继续；不可解场景有限退出。
- 对照任务完成率不降低；需要真实工具执行的任务不以“少调用/提早结束”冒充成功。
- 目标：无必要的精确重复回读较 Build269 降低至少 80%；这是待验证目标，不作为已完成收益。
- 同任务总费用及误拦不明显变坏；若更大工作区导致总费用变高，应重新调配，而非只展示命中次数。
- 最少选 3 类模型/协议，每类 30 次配对试验作为初步观察；报告每类分母、失败类型和置信区间。30 次零事件也不能称 0%（粗略 95% 上界约 10%），不许编“循环概率已经降至 1%”。
