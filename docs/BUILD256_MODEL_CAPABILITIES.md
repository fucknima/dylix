# Build 256：模型能力与深度思考适配

## 排查结论

Dylix 原实现仍有三条不一致的限制：切换模型会先发送文本探测，未知图片能力不能使用部分截图工具，只声明支持 reasoning 而未列出档位的模型可能不显示控制项。另有快捷诊断失败覆盖此前成功证据的问题。

参考已核对的 OpenMinis revision `1a71df0f381cefde80bf912b723de6f9831bc177`：

- `src/ios/Providers/ModelEntry.swift` 将服务元数据和用户覆盖分开，刷新不抹掉用户配置。
- `ModelsDevAPI.swift` 使用 models.dev 补充声明，区分当前供应商与跨供应商参考。
- `Thinking/ThinkingRuleResolver.swift` 根据端点、模型声明和族规则适配参数，没有“必须通过付费探测才能解锁”的统一要求。

Dylix 继续使用 UIKit / Objective-C 自身实现，没有移植 Minis 的整个 Swift 运行时。能力目录从其固定 models.dev 快照生成，保留原 MIT 声明与来源摘要。

## 新行为

1. 选模型只做本地配置检查，不发探测请求。文本、流式及未知图片和工具能力可以直接尝试；模型切换不会终止正在运行的任务。
2. 能力顺序为：当前端点/协议/模型的手动覆盖、同范围成功响应、当前服务明确声明、同服务离线目录、跨服务正向参考、模型族、未知。跨服务参考不携带禁止标记。
3. 失败诊断只记录“本次失败/未证实”，不自动禁用能力，也不清除同范围已有成功证据；其他范围的旧证据不会被新探测继承。实际工具权限仍独立受原审批逻辑控制。
4. 补齐 vision、tools、reasoning、modalities、reasoning_options 等字段别名；模型列表刷新保留手动设置。
5. 深度思考区分强度、开关、预算与固定思考。端点方言优先，兼容 OpenAI/Responses/OpenRouter、Claude、Gemini、硅基流动等已有协议；只声明支持但没有档位时提供注明未实测的兼容控制，默认不额外发参数。固定思考模型不伪造强度档位。
6. FLEX 的模型列表同时提供有效能力、实测能力与思考配置；截图、网页截图、普通会话使用同一图片判定。明确禁用图片时返回可处理错误，不静默丢失历史图片。
7. 设置逐项显示能力来源。诊断是可选的；可以手动适配中转别名，但不会将手动启用显示为实测成功。
